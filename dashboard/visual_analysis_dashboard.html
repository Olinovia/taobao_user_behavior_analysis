品类经营框架

规模 × 转化 × 决策周期

高规模 + 高转化 保供给、保曝光、强化关联推荐。
高浏览 + 低转化 优先排查详情、价格、信任信息和推荐匹配。
高加购 + 低成交 重点验证价格权益、库存提示和召回机制。
长决策周期 更适合内容解释、对比能力和长期触达，而不是一次性强促销。

项目研究边界

样本仅覆盖10天内的历史行为数据

本项目用于展示数据分析与产品运营方法，样本约覆盖10天，与2026年真实电商业务环境存在时间与业务背景差异。因此这里的结论用于说明“如何从数据发现问题”，策略用于展示分析到方案的推导方式，不把历史结果直接当作2026年的实时业务结论。

产品判断

数据问题与2026电商产品演进方向是一致的

本项目历史数据指出的是“决策链路中段存在损失”；2026年的主流电商 AI 能力则在用比较、价格跟踪、个性化研究和 Agent 执行缩短这段链路。它适合形成“数据发现 → 行业对照 → 产品机会”的求职作品集闭环，但不应被表述为对历史数据因果关系的验证。

11｜作品集项目总结

从数据分析到业务洞察，再到产品运营与 AI 能力设计的完整思路，归纳数据分析项目全流程。
01｜数据分析

从指标到异常

建立经营指标、行为结构、活跃趋势、漏斗、用户分层、品类与复购口径，先回答“发生了什么”。

02｜业务洞察

从异常到问题

把 PV 高、意向弱、品类差异、时段差异翻译成用户决策、产品体验与运营承接问题。

03｜产品运营

从问题到策略

按用户阶段、品类和时间窗口设计召回、推荐、详情页和生命周期运营动作。

04｜AI产品

从规则到智能

进一步把静态规则升级为 AI 商品决策助手、意图评分、智能推荐与 Agent 触达。

05｜实验验证

从策略到指标

为策略定义核心指标、护栏指标和 A/B Test，保证方案可验证、可迭代。

06｜看板呈现

把分析变成作品集

HTML 用一条主线串起图表、洞察、产品问题、行业对照和实验指标，服务面试沟通。
