# 用户行为看板设计说明

#### HTML 看板与 Markdown 分析报告的结构、KPI、图表布局与面试讲解思路

> **项目定位**
> 本项目以公开淘宝 `UserBehavior.csv` 历史样本为基础，围绕用户、商品、类目、行为、时间五个维度进行用户行为分析，并将分析结果进一步整理成 Markdown 分析报告与 HTML 可视化看板。
>
> **当前时间说明**：页面中的产品运营 / AI 产品建议是站在当前求职作品集视角，对历史数据发现进行产品化表达，不代表 2026 年实时业务结论。

html可视化分析看板报告： `dashboard/visual_analysis_dashboard.html`
md业务运营总结报告：`dashboard/business_summary_report.md`

---

# 一、项目看板结构

**本项目采用两层展示：md文档强调分析完整性和口径透明；html网页更强调信息层级、阅读效率和产品化表达。**


```text
                              数据分析
                                 ↓↓
                          分析报告 / 证据层 
                    ↓                          ↓
business_summary_report.md                 数据发生了什么？指标如何计算？结论从哪里来？

                      产品运营看板 / 展示用户分层
                    ↓                          ↓
visual_analysis_dashboard.html        业务问题是什么？用户是谁？应该怎么运营？产品可以怎么做？
```

因此，Markdown 不是 HTML 的文字版，HTML 也不是 Markdown 的截图版。

# 二、 visual_analysis_dashboard.html 结构与设计
**此HTML文件是一个面向AI产品经理/产品运营求职的作品集看板，用来集中展示从用户行为数据分析、业务洞察到产品运营策略、AI能力设计与实验验证的完整分析链路。**

### 网页结构
```text
主导航板块                       核心问题                                   业务结果
经营总览                    业务整体发生了什么？
  ↓
活跃趋势                    用户什么时候活跃、交易什么时候发生？             → 用户行为
  ↓
转化漏斗                    用户在哪一步流失？                             → 转化损失
  ↓
用户分层                    哪些用户值得不同方式经营？                      → 用户差异
  ↓
品类运营                    哪些品类有规模/转化机会？                       → 品类差异
  ↓
时间策略                    什么时候做运营更合适？                          → 时间差异
  ↓
复购留存                    一次购买之后还有什么价值？                      → 生命周期
  ↓
产品策略                    数据问题如何转成产品问题？                      → 产品/运营问题
  ↓
2026行业对照                当前识别的问题是否能对应到今天的产品能力方向？    → 产品机会
  ↓
实验方案                    策略如何被验证？                               → 实验验证
  ↓
项目思路                    我如何从数据走到产品决策？
```

### 板块设计
![看板网页预览](image.png)
| 看板板块 | 设计意图 | 板块内容 |
| ---------- | -------------------------------------------------- | ------------------------------------------ |
| Hero区 | 项目简介和核心指标 | 项目实现标签、核心指标如UV、DAU等 |
| 核心KPI | 规模、活跃、转化、生命周期指标 | UV、行为、业务情况等结论总览 |
| 图表分析区 | 以 `.grid2` 为主的双栏布局，包括字段、目的、结论等，延伸出运营策略、运营框架等 | 活跃趋势、转化漏斗等分析板块的折线、热力图 |
|业务策略和实验指标 |从图表分析得到的问题过渡到产品/运营策略；和现在时间线运营策略对比方向验证产品问题方向；为运营策略设置实验组添加验证指标；|用户行为深度和活跃时段问题 ->按用户+品类+时间动态排序资源策略 ->Amazon个性化购物功能 |
|项目总结 | 从数据分析到业务洞察，再到产品运营与 AI 能力设计的完整思路，归纳数据分析全流程。| 从数据分析到输出看板报告全流程归纳。|

# 四、 business_summary_report.md 结构与设计

**该md文档看板为电商业务运营团队、产品经理及数据决策者设计，将原本复杂的链式数据转化为“结论先行、动作明确”的业务管理工具，用以指导用户生命周期运营与商品链路转化优化。**

### 文档结构
```text
|---------------------------------------------------
│                    顶层：决策与执行摘要                        
│  01｜本周经营结论 (P0/P1/P2 发现与行动重点)                       
|---------------------------------------------------
│                  中层：数据全貌与归因分析                    
│  02｜经营看板 (大盘核心指标 & 行为占比)                         
│  03｜活跃与交易趋势 (DAU 趋势与交易时序)                         
│  04｜转化漏斗 (用户级 vs 强时序路径漏斗)                         
│  05｜用户分层 (RFM/行为深度模型)                                 
│  06｜品类经营 (规模、转化与决策周期)                             
│  07｜时间运营 (工作日/周末 & 小时级别分布)                        
│  08｜复购与留存 (老客流失与复购周期)                             
|-----------------------------------------------------
│                    底层：落地执行与风控机制                    
│  09｜经营总结 (流量-意向-成交链路图)                              
│  10｜运营行动单 (Owner 责任矩阵与 OKR 绑定)                      
│  11｜数据口径与风险提示 & Appendix (边界约束与名词解释)           
|-----------------------------------------------------
```

### 文档设计

当前 Markdown 中保留数据分析项目：

- 数据区间
- 数据量
- 指标定义
- 业务结论
- 漏斗口径
- 品类数据
- 用户分层
- 时间分析
- 复购分析
- 数据风险提示
